# Pre-push Hook — macOS 15 Build Fix

## File changed

`.githooks/pre-push`

## Problem

On macOS 15 (Sequoia), `dotnet build` consistently failed with:

```
error MSB3021: Unable to copy file "obj/Debug/net10.0/SomeLib.dll"
               to "bin/Debug/net10.0/SomeLib.dll".
Access to the path '...bin/Debug/net10.0/SomeLib.dll' is denied.
```

This happened for every solution — CatalogService, CartService, IdentityService — both in Debug and Release configurations, and even after wiping the `bin/` directory entirely.

## Root cause

macOS 15 automatically adds a `com.apple.provenance` extended attribute to files generated by compiler processes (including Roslyn). This attribute is immutable — `xattr -d` returns exit 0 but does not remove it.

The `.NET` runtime's internal `System.IO.File.Copy()` fails when the **source** file carries this attribute. The shell `cp` command is unaffected and copies correctly.

Because every `.dll` in `obj/Debug/net10.0/` and `obj/Release/net10.0/` has this attribute, MSBuild's `Copy` task — which calls `File.Copy` internally — fails every time it needs to update a file in `bin/`.

The same issue affected `appsettings.json`: the file is created by our tooling, gains the attribute, and MSBuild can't copy it to the output directory.

## Why incremental builds sometimes worked before

MSBuild compares timestamps between `obj/` and `bin/`. If the `bin/` DLL already exists and is newer than (or equal to) the `obj/` DLL, the copy is skipped entirely. This is why the hook occasionally passed: the `bin/` files were already present and up-to-date from a prior IDE-triggered build.

Once `bin/` was wiped (or never populated), every subsequent `dotnet build` needed to perform fresh copies and failed.

## Fix

Added a `seed_bin_from_obj` function that runs **before** `dotnet build`. It uses shell `cp` — which handles the `com.apple.provenance` attribute correctly — to copy every `obj/*/net*/*.dll` into the corresponding `bin/` path, then `touch`es the destination to make its timestamp newer than the source.

```sh
seed_bin_from_obj() {
  solution_dir=$(dirname "$1")
  find "$solution_dir" -path "*/obj/*/net*/*.dll" -o \
                       -path "*/obj/*/net*/*.exe" 2>/dev/null | while IFS= read -r src; do
    dest="${src/\/obj\//\/bin\/}"
    dest_dir=$(dirname "$dest")
    mkdir -p "$dest_dir"
    cp -f "$src" "$dest" 2>/dev/null || true
    touch "$dest" 2>/dev/null || true
  done
}
```

When `dotnet build` runs immediately after, it sees that every `bin/` DLL is already up-to-date (timestamp ≥ `obj/` DLL) and skips the copy step. Compilation still runs normally — Roslyn recompiles from source and writes new `obj/` DLLs. Only the final copy step is bypassed.
